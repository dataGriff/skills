# Comments: keep the why, rename the what

## A good comment

Says something the code cannot: a constraint, a consequence that is not
visible here, a workaround and what it works around, a reference to a
ticket, RFC, spec section, or a decision still in force. Examples worth
keeping:

```python
# Round half-even: ledger reconciliation needs banker's rounding (FIN-212)
# never log card_token: PCI scope (SEC-7)
# Retry once: the PSP returns 502 for ~1s after a deploy (see INC-88)
```

Every one of these would cost a future reader a wrong guess if deleted.

## Comments that go

- Restates the code: `# increment count` above `count += 1`.
- Commented-out code: git has it.
- Attribution and dates: git has those too.
- Banners and separators.
- TODO/FIXME with no owner or ticket, or waiting for something that already
  happened. A TODO with a live ticket stays.
- Autogenerated stubs ("Constructor.", "Gets the value.").

## The rename/extract recipe

For a comment that exists because a name is bad:

1. Say what the comment compensates for: a parameter nobody can read, a
   block whose purpose is not visible, a return value with a hidden case.
2. Choose the name that makes the comment redundant. Prefer the domain word
   the comment already uses (`subtotal_minor`, `is_first_order`,
   `apply_bonus`).
3. Rename, or extract the block into a function with that name. Keep the
   body byte-for-byte; extraction moves code, it does not edit it.
4. Update every call site — grep tests, docs and config for the old name,
   and keyword arguments for renamed parameters.
5. Run the tests.
6. Delete the comment.

Python, before:

```python
def calc(d, r, f):
    # d = subtotal in minor units, r = discount rate, f = first order
    if f:
        r = r + FIRST_ORDER_BONUS
```

After:

```python
def apply_discount(subtotal_minor, rate, is_first_order):
    if is_first_order:
        rate = rate + FIRST_ORDER_BONUS
```

TypeScript, before:

```ts
// walk the tree and collect every node whose status is failed
const out: Node[] = [];
walk(root, (n) => { if (n.status === "failed") out.push(n); });
```

After:

```ts
const failedNodes = collectWhere(root, (n) => n.status === "failed");
```

## Out of scope

- A rename that changes a public export or a wire format is an API change:
  leave it, and put the proposal in the audit.
- Anything beyond rename and extract — reordering statements, merging
  conditions, changing a default — is a behaviour change, however small it
  looks. Not this pass.
